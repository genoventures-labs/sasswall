# Release Notes Template (Enterprise Standard)

Use this template for every Sasswall release to keep notes uniform, professional, and operationally clear.

## Title

`Sasswall vX.Y.Z`

## Release Date

`YYYY-MM-DD`

## Executive Summary

Brief, factual summary of what this release delivers and why it matters for operators/security teams.

## Highlights

- Primary capability or improvement #1.
- Primary capability or improvement #2.
- Primary capability or improvement #3.

## Added

- New feature or subsystem.
- New API/config/CLI behavior.

## Changed

- Behavior change or improvement.
- Performance or operational adjustment.

## Fixed

- Defect resolved with clear impact.
- Stability or correctness fix.

## Security and Risk Notes

- Security-relevant behavior changes.
- Known limitations or explicit non-goals.

## Operational Impact

- Configuration changes required (if any).
- Restart/reload requirements.
- Observability/logging/metrics changes.

## Upgrade Guidance

1. Pre-upgrade checks.
2. Upgrade steps.
3. Post-upgrade validation.

## Compatibility

- Backward compatibility statement.
- Breaking changes (if none, explicitly state none).

## Checksums and Artifacts

- `sasswall_linux_amd64`
- `sasswall_linux_arm64`
- `sha256sums.txt`

## References

- Changelog: `CHANGELOG.md`
- Docs: relevant docs links for new features

## Style Rules (Required)

- No emojis.
- Use concise, formal language.
- Prefer factual statements over marketing phrasing.
- Keep sections in this exact order.
